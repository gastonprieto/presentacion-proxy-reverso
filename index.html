Bienvenida. Ya vimos el load balancer: está adelante y reparte pedidos entre copias iguales de un servidor. Hoy vemos una pieza que también está adelante, pero que decide a dónde va cada pedido según qué pide: el proxy reverso. Al final, el API gateway como caso particular. Pregunta para la clase: si una app tiene usuarios, órdenes y pagos como servicios separados, ¿cómo sabe el navegador a cuál pegarle?
